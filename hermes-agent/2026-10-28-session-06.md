### 2026-10-27 09:04-09:10 | iSH terminal idea

- Proposal: use iSH (Alpine Linux on iPhone) with SSH to reach Hermes, instead of WhatsApp.
- Verified (iSH guide): `apk add` installs OpenSSH; standard `ssh` works. iSH emulates x86, so it's slower, and it pauses when you switch apps.
- Limit: <home LAN addresses> addresses only exist inside the home network, so iSH only works on home Wi-Fi without a VPN. Never open SSH to the internet with port forwarding.
- Middleman comparison: self-hosted WireGuard (no third party) vs. Tailscale (coordination company sees metadata, not verified) vs. WhatsApp (Meta). Messaging gateways also let outside messages instruct Hermes.

### 2026-10-27 09:16 | WireGuard cost research

- WireGuard software on the Pi: $0 (in the Linux kernel since 5.6).
- WireGuard iPhone app: free, App Store privacy label "Data Not Collected" (verified).
- Possible costs: dynamic DNS (free options exist, not verified) and a relay server if behind CGNAT.
- CGNAT check: a router WAN address in 100.64.0.0 to 100.127.255.255 means CGNAT (verified, self-hosting guide).

### 2026-10-27 23:14-23:41 | INCIDENT: locked out of router settings

- iPhone and PC both blocked from the settings page.
- tplinkwifi.net loaded TP-Link's "Trying to configure the Router?" help page (name resolved outside the router). Browser VPN was confirmed off.
- `ipconfig /all` showed the PC was on **ethernet** (...7D-96), which was not on the allowed list; its Wi-Fi adapter was the allowed one.
- Switched PC to Wi-Fi (<PC LAN address>, correct MAC). Still blocked.
- `ping <router address>`: 4/4 replies. `Test-NetConnection` ports 443 and 80: **False**. Router restart did not help.
- Diagnosis: the router was enforcing the allowed list and refusing this PC.

### 2026-10-27 23:46-23:56 | Recovery with MAC spoofing

- Set the PC Wi-Fi adapter's Network Address to the iPhone's old allowed address (...9C-C1) in Device Manager.
- Router answered; Firefox showed a self-signed certificate warning (expected for a router; never click through on public sites).
- User turned **Access for All LAN Devices back on** ("I trust every device in this house"). iPhone confirmed working.
- Security lesson: MAC-based allow lists are weak, since any device on the network can copy an allowed address.
- Spoof undone: Network Address set to **Not Present**; `ipconfig /all` confirmed the real Wi-Fi MAC (...10-E9).
