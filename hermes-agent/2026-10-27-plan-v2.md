# Hermes Agent on Raspberry Pi 4: Plan v2 (iSH Terminal)

**Decided:** 2026-10-27 09:17 ET
**Change:** Talk to Hermes through **SSH from the iSH app on the iPhone**, not a messaging app (Telegram/WhatsApp). Remote access away from home comes later through **self-hosted WireGuard** (no outside company in the middle).

## Why the switch

- No messaging company sees your conversations with Hermes.
- No messaging gateway means outsiders can't send Hermes instructions through a chat app.
- iSH and the WireGuard iPhone app are both free; the WireGuard app's App Store label says "Data Not Collected."

## What gets cancelled

- **Old Phase 5 (Telegram/WhatsApp gateway):** cancelled.
- **Old Phase 6 (gateway auto-start):** cancelled. The installed gateway service stays **disabled**; it can be removed later.

## Tradeoffs to accept

- iSH works only on home Wi-Fi until WireGuard is set up.
- iSH pauses when you switch apps, which can drop the SSH session. Phase D fixes this.
- No push notifications from Hermes.

## Phase A: Finish OpenRouter basics

1. Generate a full set of OpenRouter backup codes; write them on paper.
2. Sign out the Pi's OpenRouter browser session (X11).
3. Add $5-10 in credits; Auto Top-Up OFF.

**Done when:** backup codes are on paper, and the balance is above $0.

## Phase B: First Hermes test (from the PC)

1. SSH into the Pi from PowerShell.
2. Run `hermes`, send one tiny test message, then exit.
3. Check usage on the OpenRouter Activity page.
4. Confirm the GLM 5.2 vs 5.3 choice.

**Done when:** Hermes replies, and the cost shows on OpenRouter.

## Phase C: iSH on the iPhone (home Wi-Fi)

1. Install iSH Shell from the App Store.
2. Install the SSH client (`apk update`, then `apk add openssh-client`).
3. Connect to the Pi; verify the fingerprint (AGVlkj ... ZyWNwg).
4. If iOS asks for local network access, allow it.
5. Run `hermes` from the phone.

**Done when:** you can chat with Hermes from iSH at home.
**Risk:** one guide claims iSH lacks local network access. Test first.

## Phase D: Keep sessions alive (tmux)

1. Install `tmux` on the Pi. It keeps a terminal session running on the Pi even when your phone disconnects.
2. Start Hermes inside tmux, close iSH, reopen it, and reattach. Hermes should still be running.

**Done when:** a dropped connection no longer kills Hermes.

## Phase E: Harden SSH (before anything is reachable from outside)

1. Create an SSH key on the iPhone (in iSH) and on the PC.
2. Copy both public keys to the Pi.
3. Test key login from both devices.
4. Turn off password login on the Pi.
5. Consider a login-attempt blocker.

**Done when:** only your two devices, holding their keys, can log in.
**Why first:** keys can't be guessed like passwords. This must be done before remote access exists.

## Phase F: Network check (TP-Link router)

1. Get the router model number from the sticker on the bottom.
2. Log into the router admin page and find the WAN/Internet IP. Check if it starts with 100.64 through 100.127 (if so, you're behind CGNAT).
3. Check whether the router has a built-in WireGuard VPN server.
4. Check whether the router has built-in dynamic DNS.

**Done when:** we know which WireGuard setup is possible.

## Phase G: WireGuard remote access

- **Option 1 (preferred, if supported): WireGuard server on the TP-Link router.** No port points at the Pi.
- **Option 2: WireGuard server on the Pi**, plus one UDP port forward on the router.
- **If CGNAT:** ask the ISP for a public IP, or use a small relay server (extra cost; privacy review).

Steps:
1. Set up the server (router or Pi).
2. Set up dynamic DNS (privacy review if it's a free service).
3. Install the WireGuard iPhone app and import your config. Never photograph the config or its QR code.
4. Test from **cellular data**, not Wi-Fi: connect WireGuard, then SSH with iSH.

**Done when:** you can reach Hermes from anywhere, and the Pi still isn't directly exposed to the internet.

## Phase H: Network isolation and Pi firewall

1. Decide: guest network vs. firewall-only. A VPN may land on the main network, which guest isolation could block. Choose after Phase G.
2. Add a Docker-aware firewall on the Pi:
   - allow SSH only from the home network and the VPN;
   - block the Pi from starting connections to other home devices;
   - allow internet access.

**Done when:** the Pi can reach the internet and you, but not your other devices.
