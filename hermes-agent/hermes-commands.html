Hermes Agent on Raspberry Pi 4 — Commands

Condensed printable guide. Sources: Hermes command reference (2026-10-22), sessions 01–04, Sharp TV display fix, and Plan v2 (2026-10-27). Run commands one at a time; wait for the prompt to return before the next. Paste in Pi Terminal: Ctrl+Shift+V. Paste in PowerShell (SSH): right-click. Never put API keys, passwords, or tokens on the command line, in notes, or in photos. Where you are: duppy_coder@hermes-pi = on the Pi; PS C:\... = on the Windows PC.

1. Basics and checks (Pi)

clear
df -h /
free -h
hostname -I
cat /proc/cmdline
echo $XDG_SESSION_TYPE   # wayland = wlr-randr steps; x11 = xrandr steps

2. System updates (Pi)

sudo apt update
sudo apt full-upgrade -y   # can take 10–20 minutes
apt list --upgradable   # no output = fully up to date
sudo reboot

3. Display fix — Sharp TV, Wayland (Pi's own Terminal, not SSH)

The fix is 1360x768. The TV treats it as a computer mode and shows it pixel for pixel, with no cropping. Known gap: it resets after screen sleep (kanshi fix still pending).

wlr-randr   # output name for this TV: HDMI-A-2
wlr-randr --output HDMI-A-2 --mode 1360x768   # temporary until reboot
wlr-randr --output HDMI-A-2 --mode 1280x720@60Hz   # fallback if screen goes blank
cat /etc/xdg/labwc/autostart   # look for lxsession-xdg-autostart
mkdir -p ~/.config/autostart
nano ~/.config/autostart/display-fix.desktop

File contents (4 lines):

[Desktop Entry]
Type=Application
Name=Display Fix
Exec=sh -c "sleep 3 && wlr-randr --output HDMI-A-2 --mode 1360x768"
cat ~/.config/autostart/display-fix.desktop   # check it, then sudo reboot

Save in nano: Ctrl+O, Enter, Ctrl+X. X11 variant (Parrot): replace wlr-randr with xrandr, output HDMI-2, same 1360x768 mode.

5. Hermes install — safe method (Pi)

curl -fsSL https://hermes-agent.nousresearch.com/install.sh -o install.sh
ls -l install.sh
less install.sh   # read it; q to quit
echo $HERMES_REPO_URL   # should print blank (no download redirect set)
grep -oE 'https?://[^" )]+' install.sh | sort -u   # expect only github.com/NousResearch, github.com/astral-sh/uv, *.nousresearch.com
bash install.sh
source ~/.bashrc
hermes doctor

6. SSH from the Windows PC to the Pi

systemctl is-active ssh   # on the Pi; should say active
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub   # on the Pi; expect SHA256 starting AGVlkj, ending ZyWNwg
ssh duppy_coder@   # on the PC (PowerShell)

Type 'yes' only if the fingerprint matches. Type the password promptly at the prompt.

7. Docker Engine, official repo (Pi)

sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-doc docker-buildx podman-docker containerd runc | cut -f1)
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
gpg --show-keys /etc/apt/keyrings/docker.asc   # must be 9DC858229FC7DD38854AE2D88D81803C0EBFCD88
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/debian
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update   # expect Suites: trixie, Architectures: arm64
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker run hello-world
sudo groupadd docker
sudo usermod -aG docker $USER
newgrp docker
docker run hello-world

Risk: the docker group gives root-level privileges. Accepted knowingly on 2026-10-21.

8. Hermes management (Pi)

hermes doctor   # health check
hermes setup model   # change model/provider; paste a key once, nothing else in the field
hermes setup terminal
hermes setup tools
hermes tools   # turn tools on/off
hermes setup telemetry
hermes config
hermes config edit   # secrets live in ~/.hermes/.env — never photograph it
hermes   # start chatting
hermes update   # run regularly for security fixes

Do not run hermes doctor --fix until its changes are reviewed (npm vulnerabilities are fixed upstream, not locally).

10. Plan v2, Phase C: iSH on the iPhone (home Wi-Fi only until WireGuard)

apk update
apk add openssh-client   # in iSH, after installing iSH Shell from the App Store
ssh duppy_coder@   # verify the fingerprint, then run: hermes

If iOS asks for local network access, allow it. Risk: one guide claims iSH lacks local network access — test first. iSH pauses when you switch apps, which can drop the session; Phase D fixes that. No push notifications from Hermes.

11. Plan v2, Phase D: Keep sessions alive with tmux (Pi)

sudo apt install tmux
tmux new -s hermes
hermes   # start Hermes inside tmux
# Detach: Ctrl+B, then D.  Close iSH, reopen it, SSH back in, then:
tmux attach -t hermes
tmux ls   # list sessions

12. Plan v2, Phase E: Harden SSH — keys before any remote access (do in this order)

ssh-keygen -t ed25519   # on the iPhone (in iSH) and on the PC — one key per device
ssh-copy-id duppy_coder@   # copy each public key to the Pi
ssh duppy_coder@   # test key login from both devices FIRST
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
sudo nano /etc/ssh/sshd_config   # set: PasswordAuthentication no
sudo systemctl restart ssh

Done when only your two devices, holding their keys, can log in. Consider a login-attempt blocker as well.

13. Plan v2, Phases F–H: Network check, WireGuard, isolation (checklist, no Pi commands)

  • F — TP-Link router: model number from the sticker on the bottom; WAN/Internet IP in the router admin page (100.64–100.127 = CGNAT); does it have a built-in WireGuard server? Built-in dynamic DNS?
  • G — WireGuard: Option 1 (preferred, if supported): server on the router, no port points at the Pi. Option 2: server on the Pi + one UDP port forward. If CGNAT: ask the ISP for a public IP, or use a small relay (extra cost; privacy review). Set up dynamic DNS (privacy review if free). Install the WireGuard iPhone app, import the config — never photograph the config or its QR code. Test from cellular data, not Wi-Fi: connect WireGuard, then SSH with iSH.
  • H — Isolation: decide guest network vs firewall-only after Phase G (a VPN may land on the main network, which guest isolation could block). Pi firewall (Docker-aware): allow SSH only from home network and VPN; block the Pi from starting connections to other home devices; allow internet access.

15. Password incident recovery (Pi)

clear
history -c && history -w
passwd

Use only if a password is ever typed at a normal prompt (not a password prompt).

16. Shut down or restart (Pi)

sudo shutdown now   # wait until the green light stops blinking before unplugging
sudo reboot

Do NOT do these

  • Pipe the Hermes installer straight into bash without reading it first.
  • Use 1920x1080 to fix TV cropping — it still crops. Use 1360x768.
  • Add kernel margins in /boot/firmware/cmdline.txt — Wayland ignores them.
  • Create ~/.config/labwc/autostart — it replaces the system startup file and you lose the taskbar and desktop.
  • Set up Telegram/WhatsApp gateway or gateway auto-start — cancelled in Plan v2.
  • Enable remote access before SSH keys are working and password login is off.
  • Put API keys, passwords, or tokens on the command line, in notes, or in photos; photograph a WireGuard config or QR code.
  • Run hermes doctor --fix before its changes are reviewed.
